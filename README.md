# token-os

**一台没有操作系统的 ARM 机器，靠云端吐出的 token 自己活着。**

裸机 aarch64 内核。没有 Linux，没有 libc，没有标准库。
内核里住着一个 agent，它有自己的记忆、自己的工具表、自己的压缩策略——
你在云端跟模型说话，token 从串口流进来，内核自己决定下一步写哪个寄存器。

> 2026-11-17 · 从零到一个能跑起来的 agent，用了大半天

---

## 这是什么

三段话：

1. **它不是聊天机器人。** 没有聊天窗口，没有网页，没有 App。
   输出是串口上的字节和寄存器里的电平。
2. **它不是"树莓派跑个 Linux 再调 API"。** 这台机器上电后执行的第一条指令，
   是仓库里 `startup.s` 的第 8 行。
3. **它是把 token 当作电信号来对待。** token 到达的那一刻不是"显示成文字"，
   而是落成一条事件，然后触发一个动作——可能是打印一个字符，也可能是写一个寄存器。

它现在真的会动手。下面这些字符，是模型在十分钟里**自己定义工具、自己调用**打出来的：

```
----------
[ARM] ok
```

## 它现在能做什么（实测，不是设想）

2026-11-17 上午，连续 10 分钟无人干预：

| 指标 | 实测值 |
|---|---|
| 模型请求 | **582** 次 |
| 工具执行 | **456** 次 |
| 模型自己定义 / 改写的工具 | **171** 个 |
| 上下文压缩 | **184** 次（摘要 + 遮蔽，日志一条不删） |
| 帧校验失败 | **0** |
| 云端错误 | **0** |
| 花费 | 约 ¥1.5（估算） |

它造出来的工具长这样（`script` 是一段用分号拼起来的小脚本）：

```
[新工具] line  = u:-;u:-;u:-;u:-;u:-;u:-;u:-;u:-;u:-;u:-
[新工具] box   = u:+;u:-;u:-;u:-;u:+;u: ;u:|;u: ;u: ;u: ;u:| ...
[新工具] sep   = u:-;u:-;u:-;u:-;u:-;u:-;u:-;u:-;u:-;u:-
[新工具] tag   = u:[;u:A;u:R;u:M;];u: ;u:o;u:k
```

`u:X` 打印字符，`w:地址,值` 写寄存器，`d:毫秒` 延时。
内核里没有编译器，但有一个几十行的解释器——**模型在给自己扩能力，内核负责解释执行。**

## 它是怎么工作的

```
   云端模型                     你的机器
  ┌─────────┐            ┌──────────────────────────────┐
  │ DeepSeek│            │  QEMU / 将来的真板子          │
  │   API   │            │                              │
  └────┬────┘            │  ┌────────────────────────┐  │
       │ HTTPS           │  │  token-os 内核（裸机）  │  │
  ┌────▼─────┐  帧协议   │  │                        │  │
  │ relay.js │◀─────────▶│  │  事件日志 → surface     │  │
  │ 中转     │  UART1    │  │  工具表 → 寄存器        │  │
  └──────────┘           │  │  压缩器 → 摘要          │  │
                         │  └───────────┬────────────┘  │
                         │              │ UART0          │
                         │         人的控制台            │
                         └──────────────────────────────┘
```

分四层，每层只做一件事：

| 层 | 职责 | 位置 |
|---|---|---|
| **中转** | 把内核发来的帧原样翻成 HTTPS；把返回装成帧送回去。不存任何对话状态。 | `relay.js` |
| **链路** | `A5 5A + type + len + payload + CRC8`。中断里只把一帧拷进作业槽。 | `main.c` |
| **agent** | 事件日志、surface 投影、工具表、循环、压缩。全在主循环里做。 | `agent.c` |
| **硬件** | 串口、GIC、定时器、寄存器读写。 | `main.c` |

### 最值得说的一件事：日志和"模型能看到的"是两回事

这是从 DeepSeek Harness 抄来的骨架，也是整个项目最关键的设计。

```
事件日志（永久，append-only）
  [目标] [模型说] [调工具] [工具结果] [模型说] [调工具] ...
         └──────── 被遮蔽 ────────┘
                  ↓
surface（模型能看到的窗口）
  [系统提示] [摘要 of 被遮蔽那段] [最近几条原文]
```

压缩**不删日志**。它写一条摘要，然后把"模型能看到的起点"往后推一格。
好处有三个：审计永远完整、压缩可回滚、摘要失败系统也不会崩。

### agent 的循环

```
上电 → 日志里写下目标
  ↓
组装 messages（system + surface）→ 带 tools 发请求
  ↓
收 FINAL：finish_reason / content / tool_calls
  ↓
有工具调用？→ 执行 → 结果写回日志 → 回到上一步
没有？      → 写个"继续" → 开下一轮
  ↓
surface 超预算？→ 请求摘要 → 遮蔽 → 摘要进入新 surface
```

| 时间 | 里程碑 | 证据 |
|---|---|---|
| 07:15 | 第一版裸机内核跑通：串口打印 + 1 Hz 心跳 | 早期启动日志 |
| 07:23 | 换成定时器中断驱动，加看门狗（主循环卡死 5 秒报警） | 空转 6 秒只耗 0.083 s CPU |
| 08:00 前后 | token 链路打通：内核自己拼请求，云端 token 落进 `ctx[]` | 10 分钟 250 轮、173 939 个 token 帧、0 坏帧 |
| 08:20 前后 | 缓冲区 64 KiB → 1 MiB，第二次十分钟 | 382 轮，占用 21.8%，75% 水位线没碰到 |
| 09:00 前后 | agent 版：事件日志 + surface + 工具 + 循环 + 压缩 | 本文档所有数据来自这一轮 |

中途踩了四个真坑（都修了，细节见 [`docs/agent-in-kernel.md`](docs/agent-in-kernel.md)）：

1. **把重活放进中断** → 串口 FIFO 溢出，下一帧直接丢。
2. **帧头 `A5 5A` 撞上中文 JSON 载荷** → 解析器误判，整帧丢失。
3. **一次灌整帧** → 4 KB 写进 16 字节 FIFO，丢 90%。
4. **QEMU 的 chardev 会卡死** → 停在"等前台开口"，中断再也不来。

## 快速开始

依赖：`qemu-system-aarch64`、`clang`（含 lld）、`make`、`node`。

```bash
cp key.txt.example key.txt     # 把一行 API key 写进去
make                           # 编译出 kernel.elf
bash run-token.sh 600          # 跑 10 分钟：内核 + 中转一起起来
```

看它在干什么：

```bash
tail -f log/console.log        # 内核控制台：它说的话、调的工具、画的东西
tail -f log/relay.log          # 中转：每次请求的状态（不含 key）
```

只想看心跳、不接云端：

```bash
make && make run               # Ctrl-A X 退出
```

> **关于 key**：`key.txt` 在编译时被写进内核镜像（`key.inc` → `API_KEY`），
> 每次请求由内核自己带出来，中转只转发、不落盘。
> `key.txt` / `key.inc` / `*.elf` 都在 `.gitignore` 里，**不要提交。**

## 五条不破的规则

1. **中断里只搬字节。** 解析、执行工具、打印，全在主循环。中断里慢一拍，FIFO 就溢出。
2. **先记日志，再动硬件。** 每一次工具调用和结果都是事件，可回放、可审计。
3. **日志和 surface 分开。** 压缩是改投影，不是删除。
4. **大模型不在实时路径上。** 它请求工具，不直接写寄存器；写之前有表、有检查。
5. **先慢后快。** 软件模拟 → 硬件虚拟化 → 真板子。每一步都可回滚。

## 已知边界（诚实版）

| 还没有 | 意味着什么 |
|---|---|
| **持久化** | 事件日志在 RAM 里，断电就没了。要补 virtio-blk，"上下文存在机子里"才算物理成立。 |
| **工具权限** | 目前只按名字匹配，没有 capability 位。模型理论上能写任意物理地址。 |
| **压缩质量评估** | 184 次摘要里有没有丢关键信息，还没有指标。 |
| **真硬件** | 只在 QEMU `virt` 上跑过。时序、缓存、真实外设都是空白。 |
| **多任务** | 单核、单循环、一次一个工具调用。 |

## 路线图

- **M1** ✅ 内核执行一次工具调用
- **M2** ✅ 循环：多步、回填结果、步数上限
- **M3** ✅ 压缩 + surface 投影（**冷启动的持久化还差 virtio-blk**）
- **M4** 事件日志落盘，重启后从日志尾部恢复
- **M5** 工具权限：能力位 + 地址范围 + 高危审批
- **M6** 上真板子（先硬件虚拟化，再裸机）

## 为什么还是开源了

作者原话，一字未改：

> 随便吧，都没啥意义，这点工作量其实很多 AI 看一眼都重新造个新轮子，
> 提了协议也没用，但我还是想做出点微小的贡献，全当为了 DeepSeek 大肥鱼吧。
> 不过是我先想到的。

比任何"项目愿景"都诚实，所以放这儿。

说完他还追问了一句：**怎么证明是我先想到的呢？**

答案是：**证明不了。想法没有时间戳，只有作品有。**

这个仓库因此不声称任何"首创"。别人哪怕承认你先想到，也不会因此少写一行代码；
反过来，别人先发了论文，也不影响你把这堆代码跑起来。真正稀缺的从来不是第一个念头，
是念头之后那三小时的调试——串口不出字、中断不来、寄存器写错一个字就死机。

能查证的只有一件事：**这个东西在 2026-11-17 这一天，确实存在过并且跑起来了。**
